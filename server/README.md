# שרת אלבום הבלוז

שרת קטן בלי אף חבילה חיצונית. מריצים אותו על Node 20 ומעלה.

```
node server/server.mjs
```

הוא עושה שני דברים: מגיש פוסטים מאינסטגרם כקטעי קריאה, ומגיש את עשרת המשחקים
האחרונים ועשרת הבאים. הכול נשמר בדיסק, כך שגם אם ספק חיצוני נופל האפליקציה
ממשיכה לקבל את המידע האחרון שהצליח להגיע.

---

## התקנה

```bash
cp server/config.example.json server/config.json
# ערוך את הקובץ, לפחות את adminToken
node server/server.mjs
```

הפעלה ראשונה יוצרת את `server/data/` עם המטמון והתמונות השמורות.

בסוף, בתיקיית האפליקציה:

```bash
cp app-config.example.js app-config.js
# ערוך את apiBase כך שיצביע לכתובת השרת
python3 tools/build.py
```

בלי `app-config.js` האפליקציה פשוט עובדת עם תוכן לדוגמה ולא מנסה לפנות לרשת.

## 1. חדשות מאינסטגרם

### הבעיה
אינסטגרם לא מאפשרת לקרוא פוסטים של חשבון שאינך מנהל. אין לזה API, ואין
דרך חוקית לעקוף את זה. גרידה של הדף מפרה את תנאי השימוש ונשברת כל כמה שבועות.
לכן יש שני מצבים.

### מצב `curated` — ברירת המחדל
רשימה שאתה מנהל. עובד לכל חשבון, גם כזה שאינו שלך.

פתח `http://localhost:8787/admin`, הזן את `adminToken`, והדבק לכל פוסט את
הכיתוב, כתובת התמונה והקישור לפוסט. השרת מוריד את התמונה אליו ומגיש אותה
מקומית, כך שהיא לא תיעלם כשאינסטגרם תפוג את הקישור המקורי.

### מצב `graph` — משיכה אוטומטית

⚠️ מטא סגרה את Instagram Basic Display API בדצמבר 2024. כל מדריך שנכתב לפני
התאריך הזה כבר לא רלוונטי. המסלול הנוכחי נקרא **Instagram API with Instagram Login**.

**דרישת סף:** החשבון חייב להיות Business או Creator. אם הוא עדיין אישי,
משנים אותו באינסטגרם תחת הגדרות ← סוג חשבון וכלים ← מעבר לחשבון מקצועי.

בחר מסלול לפי איך שאתה מנהל את החשבון:

#### מסלול א — יש לך את פרטי ההתחברות של חשבון האינסטגרם
זה הפשוט יותר, ולא דורש עמוד פייסבוק מקושר בכלל.

1. היכנס ל-[developers.facebook.com](https://developers.facebook.com) ← My Apps ← Create App.
   בבחירת סוג האפליקציה בחר **Business**.
2. בתפריט הצדדי: **Products** ← ליד **Instagram** לחץ **Set up**.
3. בחר **API setup with Instagram Login**. שים לב לא לבחור בטעות
   *API setup with Facebook Login* — זו אינטגרציה אחרת לגמרי.
4. בקטע **Generate access tokens** לחץ **Add an Instagram Account**,
   התחבר עם חשבון מועדון האוהדים ואשר את ההרשאות.
5. לחץ **Generate token** והעתק אותו.

הטוקן מהלוח הזה הוא ארוך-טווח ותקף ל-60 יום. לא צריך App Review ולא צריך
להוסיף משתמשי בדיקה — הדרישות האלה בוטלו יחד עם ה-API הישן.

```json
"news": {
  "mode": "graph",
  "graph": { "login": "instagram", "apiVersion": "v23.0", "userId": "me", "accessToken": "IGAA..." }
}
```

#### מסלול ב — אתה מנהל דרך עמוד פייסבוק, בלי סיסמת האינסטגרם
קורה כשהוסיפו אותך כמנהל לעמוד הפייסבוק המקושר. כאן מתחברים עם חשבון
הפייסבוק שלך במקום עם האינסטגרם.

1. אותה יצירת אפליקציה מסוג **Business**.
2. **Products** ← **Instagram** ← **API setup with Facebook Login**.
3. פתח את [Graph API Explorer](https://developers.facebook.com/tools/explorer),
   בחר את האפליקציה שלך, ובקש את ההרשאות `instagram_basic` ו-`pages_show_list`.
4. הרץ `GET /me/accounts` כדי למצוא את העמוד, ואז
   `GET /{page-id}?fields=instagram_business_account` כדי לקבל את המזהה
   המספרי של חשבון האינסטגרם.
5. קח **טוקן של העמוד** — הוא לא פג, בניגוד לטוקן משתמש.

```json
"news": {
  "mode": "graph",
  "graph": { "login": "facebook", "apiVersion": "v23.0", "userId": "17841400000000000", "accessToken": "EAAG..." }
}
```

#### בדיקה שזה עובד
אחרי שהזנת את הטוקן והפעלת מחדש:

```bash
curl -s localhost:8787/admin/ig-check -H 'X-Admin-Token: הסיסמה-שלך'
```

תשובה תקינה נראית כך, והיא מאשרת שהטוקן תקף ושהפוסטים נגישים:

```json
{ "ok": true, "login": "instagram", "account": "cfcilofficial", "postsVisible": 5 }
```

אם חזרה שגיאה, ההודעה של מטא מופיעה בשדה `error` ובדרך כלל אומרת בדיוק מה חסר.

#### חידוש הטוקן
במסלול א הטוקן פג אחרי 60 יום. השרת מחדש אותו לבד פעם ביום ושומר את
החדש ב-`data/token.json`, כך שכל עוד הוא רץ פעם בחודשיים אתה מסודר.
במסלול ב טוקן העמוד לא פג ואין מה לחדש.

## 2. לוח המשחקים

ברירת המחדל היא [football-data.org](https://www.football-data.org). המסלול החינמי מספיק:
עשרה משחקים אחרונים ועשרה באים, עם רענון כל חצי שעה, נמצא הרבה מתחת למכסה.

1. הירשם ותקבל מפתח במייל.
2. ב-`config.json` הזן אותו תחת `matches.apiKey`. המזהה 61 הוא צ'לסי ולא צריך לשנות.

השרת ממיר את התשובה למבנה שהאפליקציה מצפה לו — יריבה, סמל, בית או חוץ,
תוצאה, תאריך ומפעל — ומחשב גם ניצחון, הפסד או תיקו כדי לצבוע את התוצאה.
סמלי הקבוצות מורדים ונשמרים מקומית.

אם אין מפתח, השרת פשוט מחזיר רשימות ריקות והאפליקציה מציגה את כרטיס הדוגמה.

---

## נקודות קצה

| נתיב | מה מחזיר |
| :--- | :--- |
| `GET /api/feed` | חדשות ומשחקים בקריאה אחת — זו שהאפליקציה משתמשת בה |
| `GET /api/news` | פוסטים בלבד |
| `GET /api/matches` | `{past, upcoming}` |
| `GET /media/<file>` | תמונה שמורה |
| `GET /health` | בדיקת חיים ומצב ההגדרות |
| `GET /admin` | ממשק ניהול הרשימה |
| `POST /admin/news` | הוספת פוסט · דורש כותרת `X-Admin-Token` |
| `DELETE /admin/news/:id` | מחיקת פוסט |

## מטמון

חדשות מתרעננות כל 15 דקות ומשחקים כל 30. אם הספק לא עונה, השרת מגיש את
הגרסה האחרונה שהצליחה ומסמן אותה `stale: true` במקום להחזיר שגיאה.

האפליקציה שומרת עותק משלה במכשיר, ולכן היא מציגה חדשות ומשחקים גם בלי רשת
בכלל — עם באנר "מצב לא-מקוון".

---

## איפה להריץ

**בבית.** מחשב או Raspberry Pi שדולק. פשוט, ואם הוא כבוי האפליקציה מציגה
את המידע השמור.

**בענן.** Render, Railway ו-Fly מריצים את זה בשכבה החינמית. הקובץ בלי תלויות,
אז אין שלב התקנה. שים את הסודות כמשתני סביבה: `ADMIN_TOKEN`, `IG_TOKEN`,
`FOOTBALL_DATA_KEY` — הם גוברים על `config.json`.

שים לב שרוב השכבות החינמיות מוחקות את הדיסק בכל פריסה. זה מוחק את המטמון
ואת התמונות השמורות, אבל הן פשוט יורדות שוב. הרשימה המנוהלת (`data/news.json`)
כן תיעלם — במצב `graph` זה לא רלוונטי, ובמצב `curated` שמור עותק או חבר דיסק קבוע.

## הערה על התצוגה המקדימה

הפרוטוטייפ שמפורסם בצ'אט לא יכול לפנות לשרת. מדיניות האבטחה של הדף חוסמת
כל בקשת רשת החוצה, וזו מגבלה של סביבת התצוגה ולא של הקוד. בהרצה מקומית
או באפליקציית אנדרואיד ארוזה החיבור עובד רגיל.
